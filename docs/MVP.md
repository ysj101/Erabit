# エラビット（Erabit）— MVP仕様書

> **選ぶって、こんなに面白い。**
>
> 日常の意思決定をゲームに変え、自分の判断のクセを発見する。

- ドキュメント状態：MVP / v0.1
- プラットフォーム：スマートフォン優先のWebアプリ（PC対応）
- 対象：行動経済学に興味がある人、心理学に詳しくない人
- プレイ時間：1ミッション約1〜2分
- 初期収録：12ミッション・5テーマ
- アカウント登録：不要

## 1. プロダクトの目的

エラビットは、現実の出来事や身近なシチュエーションの中で選択を重ね、意思決定に影響する心理的な要因を学ぶカジュアルゲーム。

覚えてもらいたいのは専門用語の定義ではなく、**「同じ自分でも、状況や見せ方によって判断が変わるかもしれない」** という気づき。

### 提供する体験

1. 迷う余地のある現実的な状況が現れる。
2. 解説を読む前に、自分ならどうするかを選ぶ。
3. 選択結果や新しい情報が提示され、思い込みに気づく。
4. どの心理効果が関係し得るかを、短いアニメーションと具体例で理解する。
5. 学んだテーマと自分の回答が、図鑑・履歴に残る。

### プロダクト原則

- **ゲームが先、解説は後**：バイアス名を見てから「正解」を探すクイズにしない。
- **現実に結びつける**：買い物、仕事、お金、SNSなど身近な意思決定を扱う。
- **単純な正誤で裁かない**：合理性は前提条件や本人の価値観で変わる。
- **短くテンポよく**：1画面に問いかけは原則1つ。説明を一度に詰め込まない。
- **自分の変化を振り返れる**：選択だけでなく、確信度や追加情報への反応も必要に応じて残す。
- **特定の人物像を決めつけない**：回答から性格や心理特性を診断しない。

## 2. 世界観とキャラクター

プレイヤーの前に現れるのは、好奇心旺盛な白ウサギの **エラ**。青いスカーフと小さな茶色のバッグがトレードマーク。

エラは先生でも審判でもなく、「一緒に迷って、一緒に気づく」相棒。プレイヤーの回答を馬鹿にしたり、恥ずかしいと感じさせたりしない。

### デザイン方針

- 手描きの温かさを感じる、輪郭のはっきりした2Dイラスト
- クリーム・コーラル・青を中心とする明るい配色
- 感情が伝わる表情、耳とスカーフの小さな動き
- 文字量を抑え、選択肢と操作対象をはっきり見せる
- スマホでも押しやすいタップ領域と読みやすい文字

画像と使用ルールは [キャラクターガイド](CHARACTER_GUIDE.md) を参照。

## 3. MVPで実現する価値

**仮説**：知識を先に教えるより、先に自分で判断して「そうだったのか」と気づく体験のほうが、行動経済学への興味と学習意欲を高められる。

### MVPの範囲

| 対象 | MVPで行うこと |
| --- | --- |
| 端末 | iOS / Androidのモバイルブラウザ、PCブラウザ |
| 問題 | 12ミッション（うち初期検証では3問だけ先行実装） |
| 問い | タップ選択、金額スライダー、画面内タップ |
| コンテンツ | 日常の選択8、実際の出来事2、仕掛けを見抜く2 |
| 学習 | 選択後の種明かし、行動経済学の簡潔な解説 |
| 収集 | 発見したバイアスカード、プレイ履歴 |
| 振り返り | 回答履歴と「学んだテーマ」のレポート |
| 保存 | 端末の `localStorage` |
| 認証 | なし |

### MVPでやらないこと

SNSログイン、同期、オンラインランキング、友人対戦、生成AIによる自動出題、プッシュ通知、課金、心理特性の診断、ニュースの自動収集。

## 4. ゲームフロー

```text
タイトル
  ↓
ミッション一覧
  ↓
状況を知る（短い導入）
  ↓
自分の判断を入力
  ↓
新しい情報・結果・リアクション
  ↓
心理効果の種明かし（短い解説）
  ↓
自分の回答を振り返る
  ↓
図鑑更新 → 次のミッション
```

### 必須ルール

- 原則、初回の判断が確定する前に解説や正解を表示しない。
- すべての選択に結果フィードバックがある。
- 解説には「どの情報が判断に影響し得るか」を明記する。
- 選択によって「あなたは○○に弱い」と断定しない。
- 先に見せた情報による学習効果があるため、再回答は心理効果の厳密な測定とは扱わない。
- 失敗時や離脱時にも回答が失われにくいよう、ミッション進行を保存する。

## 5. ミッションの種類

### A. 日常の選択（8問）

買い物・仕事・お金・対人関係を題材に、直感で判断する。初回開発ではここから3問を実装する。

### B. 実際の出来事（2問）

公開された研究、企業の取り組み、現実のニュースなどの事実を題材に、当事者の立場で判断する。事実関係とゲーム用の脚色は区別し、元情報と確認日をコンテンツデータに保持する。

### C. バイアスを見抜け（2問）

架空のEC画面、広告、サービス申込画面などを見て、選択を誘導している可能性がある表現をタップする。単に強調表示されているだけの箇所をすべて「悪い仕掛け」とは扱わない。

| M02 | 100万円をかけた新事業 | 日常の選択 | サンクコスト |

## 6. 先行実装する3ミッション

### M01：本日限定50%OFF！

**学習テーマ**：アンカリング効果

**導入**：イヤホンに「通常30,000円 → 本日15,000円」と表示されている。

**問い**：「あなたならどうする？」

- A：今すぐ買う
- B：比較してから決める
- C：買わない

**回答後**：そのイヤホンの機能、代替候補、割引前価格の根拠がまだ分からないことを示す。エラが「安くなっていることと、欲しいものかどうかは別だね」とコメントする。

**学習**：最初に見た数字が評価の基準になることがある。割引で買うこと自体が不合理とは限らない。

**クリア条件**：選択を確定し、解説を開く。

### M02：100万円をかけた新事業

**学習テーマ**：サンクコスト効果

**導入**：事業に100万円を投資済み。今後も追加費用が必要で、市場調査の見通しも厳しい。

**問い**：「次の会議で、どう提案する？」

- A：投資済みなので続ける
- B：今後の期待収益と追加費用で再評価する
- C：今すぐ撤退する

**回答後**：すでに回収不能な支出と、これから発生する費用を別々に見せる。

**学習**：過去の費用を取り戻そうとする気持ちだけで継続を決めると、将来の選択を誤ることがある。なお「必ず撤退」が正解ではない。

**クリア条件**：選択を確定し、過去の支出と将来の見込みの違いを確認する。

### M03：みんなが買っている

**学習テーマ**：社会的証明

**導入**：SNSで話題の美容家電。「購入者の95%が高評価」と表示されている。

**問い**：「買いたいと思う？」

- A：かなり買いたい
- B：もう少し情報を見たい
- C：買いたいと思わない

**回答後**：高評価の人数、レビューの集め方、広告表示の有無などが未確認だと分かる。

**学習**：他者の評価は役に立つが、母数や偏りによって解釈が変わる。

**クリア条件**：選択を確定し、評価を見るときのチェックポイントを知る。

### ミッションに共通する表現ルール

- 「買う」＝バイアスに引っかかった、などの短絡的な判定をしない。
- 個人の回答と心理効果の関連性は「可能性」として示す。
- 解説は要点2〜3文、詳しい説明は任意で開けるようにする。
- 実際の出来事は出典を管理し、架空の会話・画面を「再構成」として区別する。

## 7. バイアス図鑑

ミッション完了時にテーマのカードを解放する。

| 項目 | 内容 |
| --- | --- |
| カード名 | 例：アンカリング効果 |
| イラスト | 原理を印象づける簡単なイラスト |
| ひとこと説明 | 40〜60文字程度 |
| 日常での例 | 1〜2例 |
| 関連ミッション | プレイ済みと未プレイを区別 |
| 自分の記録 | 選択の履歴（任意） |

図鑑は学習の進行と収集を楽しむための機能であり、心理的な弱点の診断結果ではない。

## 8. 自分の判断レポート

初期実装では次の事実だけを表示する。

- プレイしたミッション数
- 発見したテーマ数
- 各テーマでプレイした問題数
- 選択した回答と、回答日時
- 同じテーマに再挑戦した履歴

**表示しないもの**：「あなたは損失回避75%」「あなたの脳は○○型」といった、妥当性が未検証のスコアや性格分類。

将来、判断傾向を推定する場合は、問題の測定設計・提示順序・試行数・妥当性を別途検証する。

## 10. アニメーションと音

- エラの表情差分：基本・驚き・考える・ひらめき・喜ぶなど
- ボタンを押した時：短い押下アニメーション
- 種明かし：カードが開く、電球が光るなどの軽い演出
- クリア：数秒以内の気持ちよいフィードバック
- 動きが苦手な利用者向けに `prefers-reduced-motion` を尊重
- 音なしでも全内容を理解できる。音声は初期OFF

## 11. 技術構成

| 領域 | 技術 |
| --- | --- |
| UI | React + TypeScript |
| 開発環境 | Vite |
| スタイル | Tailwind CSS |
| モーション | Motion（必要な箇所のみ） |
| コンテンツ | ローカルのJSON / TypeScriptデータ |
| ローカル保存 | `localStorage` |
| 配信 | 静的ホスティング（例：Cloudflare Pages） |
| バックエンド | なし |

### データモデルの方針

**Mission**：`id`、`title`、`category`、`scenario`、`prompt`、`choices`、`reveal`、`biasIds`、`explanation`、`sources?`、`illustration`。

**PlayRecord**：`missionId`、`selectedChoiceId`、`timestamp`、`completed`、`confidence?`、`replayed?`。

**BiasCard**：`id`、`name`、`shortExplanation`、`examples`、`relatedMissionIds`、`illustration`。

**SourceRecord**：`title`、`url`、`publisher`、`checkedAt`、`isReconstruction`。実話題材では必須。

TypeScript型でフィールドを検証し、公開前に全ミッションのコンテンツ検査を行う。

## 12. 非機能要件

- モバイルファースト、幅320px相当からPCまで表示が破綻しない。
- 操作のタップ領域は原則44×44 CSS px以上。
- キーボードとスクリーンリーダーで操作できる。
- 色の違いだけで正誤や選択状態を示さない。
- 進行状態はページ再読込後にも保持される。
- データ削除が設定画面からできる。
- 外部送信するユーザーデータをMVPでは持たない。
- 初期のコア体験にネットワークAPIを要求しない。
- 実際のニュースを扱う場合は出典と確認日を記録する。

## 13. 開発フェーズと完了基準

### Phase 1：遊びの検証（3ミッション）

- タイトル・選択・結果・解説の一連の体験
- エラの基本表情とリアクション
- M01、M02、M03を最後まで遊べる
- スマートフォンで操作可能
- 5人程度の試遊で、面白かった瞬間と分かりにくい箇所を確認

### Phase 2：MVP公開（12ミッション）

- 全ミッションの導入、結果、解説が実装済み
- 図鑑と回答履歴を表示できる
- 再読込しても進捗が保持される
- 進行中の戻る操作、最初からやり直す操作が機能する
- アクセシビリティの基本テストを通過する
- 実話を題材にしたコンテンツの出典確認が完了している

### Phase 3：公開後の候補

- 新しいミッションの定期追加
- 別の場面へ知識を応用する復習問題
- ゲーム中の判断の変化を、より慎重に比較する仕組み
- 回答傾向の集計（十分な検証ができた場合）
- ネイティブアプリ化

## 14. 成功指標

**計測するもの**：初回3ミッションの完了率、12ミッションの平均プレイ数、次のミッションへの遷移率、図鑑閲覧率、再挑戦率。

**ユーザーインタビューで確認すること**：「新しい発見があったか」「自分の実生活に結びついたか」「続きをプレイしたいか」「押し付けられた・説教されたと感じなかったか」。

数値目標はテストで基準値を取得してから設定する。

## 15. MVPの最重要基準

プレイヤーが「行動経済学の問題を解いた」と感じるのではなく、**「自分の判断ってこんなに面白いのか」と感じること**。

その体験を支えるのが、現実的なシチュエーション、意外性のある種明かし、親しみやすいエラのリアクション、そして自分の選択を振り返る仕組みである。
